# 機能仕様書

## 1. 蔵書登録

### F-01 手動登録

1. 利用者がタイトルと任意項目を入力する。
2. タイトル入力が2文字以上の場合、NDL候補を最大8件表示する。
3. 候補選択時は書名、著者、出版社、出版日、ISBNをフォームへ反映する。
4. ISBNがある場合は書誌・表紙を取得してから所蔵項目を反映する。ISBNがなければ手動レコードを作る。

タイトルは必須。ISBNを入力した場合はチェックディジットを検証し、ISBN-10はISBN-13へ変換する。

### F-02 iPhone画像登録

1. iPhoneは撮影画像の下半分を優先してZXingで解析する。
2. 読取成功時はISBNと画像を送信する。失敗時は画像だけを送信する。
3. PCは画像実体を検査して保存し、ISBNがなければ複数領域・回転・二値化方式で再解析する。
4. 読取不能時は画像を残し、iPhoneへISBN手動入力を要求する。
5. ISBN確定後、書誌を取得して蔵書へ登録する。

同一ISBNがある場合は新規重複を作らず、書誌だけを更新し、読書状態・所蔵情報・メモ・並び順を維持する。

### F-02A 一括取り込み

1. 利用者は実本または電子書籍を選び、共通の保管場所または電子書籍媒体を指定する。
2. 電子書籍ではスクリーンショット方式を初期表示する。最初のステップとしてどのストアのスクリーンショットかを選択させ、選択後に電子書店のライブラリ画像を最大12枚選択できる。選んだストアが登録先の電子書籍媒体になる。
3. OCR行から書名候補を選ぶ。表紙アートで途切れた断片行は完全な書名ラベル行へ統合し、書名の直下にある著者行、レーベル・出版社行、UI文字を除外する。一覧型・グリッド型の両レイアウトに対応し、1枚あたり最大12書名を抽出する。
4. 画像は既存の画像実体検査、最大2400px縮小、PNG再構築を通した後、Windows内蔵OCRでPC内処理する。一時画像はOCR完了時に削除する。
5. 全体最大60書名を10書名ずつNDL SRUへ分割照合し、OCR書名との類似度を満たす候補だけを表示する。同じ候補は最も類似する書名だけへ割り当て、巻数違いの候補を正しい巻より上位にしない。ISBNを取得できない書名は「書名のみ」と明示して登録できる。
6. 代替方式としてISBNを1行ずつ、または`タイトル<TAB>著者`、`ISBN<TAB>タイトル<TAB>著者`形式で最大200件入力できる。TSV/TXTも同じ形式で読み込める。
7. ISBN行は書誌・表紙取得を行い、タイトル行は手動書誌として保存する。既存ISBNは重複を作らず指定した所有形態・保存先へ更新する。
8. 取り込み中に表紙を取得できなかった本は、応答後のバックグラウンド補完（F-11参照）で取り込み件数を上限に再取得する。

## 2. 書誌・表紙

### F-03 書誌統合

- openBDとGoogle Booksを並行して照会する。
- 基本書誌はopenBDを優先し、不足項目をGoogle Booksで補う。
- 両方が失敗または未登録の場合も`ISBN {isbn}`として登録を継続する。
- カテゴリは利用者の保存値、旧マンガ分類、キーワード推定の順で決定する。

### F-04 表紙キャッシュ

- openBD・Google Booksの書誌API候補を優先し、NDL書影、Open Libraryの順に補助候補としてHTTPS画像を試す。
- 許可ホスト、Content-Type、8MB上限、寸法、画素数、静止画を検査する。
- 120x160未満のプレースホルダーを除外し、最大640x960のWebPへ変換する。
- 一冊の表紙取得失敗は他の蔵書処理を停止させない。
- openBD候補が無効でもGoogle Books、NDL書影、Open Libraryの順に続行し、詳細画面の「表紙」操作でISBNから再取得できる。
- 画面上の画像読込に失敗した場合は、壊れた画像表示をアプリ同梱の既定表紙へ置き換える。本棚では表紙未取得の本のプレースホルダーへタイトルを重ねて表示する。
- 起動時にISBNのある蔵書の不足した表紙・読みを自動補完する。試行結果は`metadataCheckedAt`へ記録し、同じ本への再試行は3日間隔、1回の起動で最大15冊に抑えて外部APIの呼び出し回数を制限する。

## 3. 蔵書管理

### F-05 編集・削除

- 編集可能項目は書名、著者、出版社、出版日、ページ、読書状態、評価、棚、タグ、メモ、カテゴリ、所有形態、場所・媒体、電子URL、シリーズ、巻数、リマインダーとする。
- ISBNと内部IDは編集APIで変更できない。
- 電子URLは認証情報を含まないHTTPS URLだけ保存できる。
- 削除前にPC画面で確認ダイアログを表示する。

### F-06 検索・絞り込み・並び替え

- 部分一致対象は書名、著者、出版社、ISBN、タグ、カテゴリ、棚、物理場所、電子媒体、シリーズ名。
- 所有形態、カテゴリ、電子媒体、読書状態、出版社、著者、最低評価、シリーズ有無で絞り込む。
- 自動順は新着、名前、著者、出版社、シリーズ・巻数、場所・媒体。手動順はドラッグ結果を全ID配列として保存する。
- 名前・著者・出版社・シリーズ・場所順では対応する棚見出しを表示できる。かなは行、英字・数字は補助見出しへ分け、読みを取得できない項目は末尾の「その他」へまとめる。見出しは棚上の「仕切り」または表示設定から非表示にできる。
- openBDから取得できるタイトル・著者の読み、または利用者が編集した読みを、名前順・著者順と行見出しへ優先して使う。

### F-06A 本棚表示設定

- 本の幅を72〜132pxで変更し、高さは表紙比率に追従する。
- 同一シリーズを一つの重なりカードへまとめ、クリックで所持巻一覧へ遷移する。
- 手動並び替え中は各巻を直接ドラッグできるよう、シリーズ集約を一時的に解除する。
- 表示設定はPCのlocalStorageへ保存し、蔵書JSONには混在させない。

## 4. シリーズとリマインダー

### F-07 新刊確認

1. マンガかつシリーズ名のある蔵書をシリーズ名の比較キーで集約する。
2. NDLから同名シリーズの巻を取得し、同一巻の重複版を除く。
3. 所持最大巻より大きい最初の巻を「次に登録可能」とする。
4. 最新巻と次巻のISBN・刊行日・NDL URLを同シリーズの全所持巻へ保存する。
5. 新刊リストから次巻ISBNを登録できる。

### F-08 リマインダー

- 蔵書ごとに日付と内容を保存する。
- リマインダー画面は日付がある蔵書を表示し、当日以前を期限到来として強調する。
- OS通知やバックグラウンド通知は行わない。

### F-08A 本のパック

1日1回だけ開けるカードパック形式で、未所持の本を5冊紹介する。

- 4枠は蔵書のジャンル比率で抽選し、残り1枠を利用者の本棚に対する「レア」枠とする。未所蔵ジャンルがあればその中から無作為に選び、全ジャンルを所蔵している場合は最も冊数の少ないジャンルを使う。市場価格、絶版、発行部数は判定に使わない。
- 蔵書のあるジャンルは、同ジャンルの出版社を手がかりにNDLサーチAPIで探す。出版社が未登録なら同ジャンルの著者で探す。
- NDLは件名指定を無視し、書名順の先頭約500件しか返さないため、検索語（書名に含まれる語）と開始位置を毎回変えて結果の偏りをなくす。候補が得られない場合は条件を緩めて最大3回まで探し直す。
- 候補はopenBDへ一度の一括照会で確認し、書影がある本を優先したうえで、紹介文のある本を優先して選ぶ。
- 所蔵済みISBN、同名タイトル、パック内の重複を除外する。
- カードには書名、著者、出版社・出版年、表紙、選ばれた理由（「◯◯社の本」「未所蔵の◯◯」「所蔵が少ない◯◯」など）を表示し、紹介文を取得できた場合だけ本文を載せる。
- パックの生成には外部APIの照会が伴うため、サーバー起動時にバックグラウンドで用意する。画面は生成完了を待たず、候補が何冊決まったかを進捗として表示し、完成したら自動で切り替える。
- 生成したパックは日付とともにPCへ保存し、同じ日の再表示では外部APIを呼ばない。
- 未開封の紙封筒は上方向のドラッグで口を開き、続けて中のカード束を上へ引き抜く。取り出した5枚は時間差で裏向きに並び、利用者がクリックした札だけが表へ返る。「すべてめくる」操作も用意する。
- 裏面は全カード共通でレア枠を事前に判別できない。レア枠を表返したときだけ専用の発光、スパーク、選定理由を表示する。めくった札は日付ごとに端末へ記録し、画面を離れても続きからめくれる。
- 候補の追加は既存のISBN登録処理を使い、登録後は通常の本棚と詳細へ戻る。
- 読書傾向はPC内で選定し、蔵書一覧そのものを外部APIへ送らない。

## 5. LAN連携と持ち出し

### F-09 LAN認証

- 起動時に256bitのランダムトークンを生成し、PCのQRだけへ埋め込む。
- iPhoneの初回GETでトークンをHttpOnly・SameSite=Strict Cookieへ移し、URLから削除する。
- アプリ再起動後はトークンが変わるため、QRから再接続する。
- ループバック接続はデスクトップUIのためトークンを不要とする。

### F-10 店頭用データ

- 「出発前に同期」は最小項目をiPhoneのlocalStorageへ保存する。
- 「持ち出し保存」は外部スクリプトを含まない自己完結HTMLを返す。
- 店頭ではタイトル、著者、ISBNの部分一致とISBN完全一致による登録済み表示を行う。

## 6. データ保全

### F-11 バックアップと書き出し

- サーバー起動時、その日の最初の起動でbooks.jsonのスナップショットを`data/backups/books-YYYY-MM-DD.json`へ保存し、最新7世代だけを残す。
- PCサイドバーの「蔵書データを書き出す」から`GET /api/export/books`を呼び、`{exportedAt, count, books}`のJSONをダウンロードできる。
- いずれもPC内の保全機能であり、別媒体への外部バックアップを置き換えない。

## 7. エラー表示

- 4xxは利用者が修正できる日本語メッセージを返す。
- 5xxは内部情報を隠し、PCログ確認を案内する。
- ISBN画像読取不能は422とし、保存済みアップロード情報を返して手動補完を可能にする。
- 要求頻度超過は429、LAN認証不足は401、送信元・ネットワーク違反は403とする。
